RUN_DB_BATCH_EXPERIMENT=true DB_BATCH_OUT="$PWD/선착순_쿠폰발급_부하테스트/results/NEW-db-batch" ./gradlew --no-daemon test --tests '*DbBatchExperimentTest' --rerun-tasks
python3 선착순_쿠폰발급_부하테스트/analyze-db-batch.py 선착순_쿠폰발급_부하테스트/results/NEW-db-batch

RUN_DB_BATCH_EXPERIMENT 미지정 시 이 클래스는 실행하지 않는다. 환경 변수는 Gradle up-to-date 입력에 자동 반영되지 않을 수 있어 재현 시 --rerun-tasks 사용.
두 JUnit 메서드: 먼저1건/10건 DB오류 롤백·재시도·재전달, 이후 네 번 성능/정합성 비교.
같은 테스트 JVM/격리 MySQL. Redis/Kafka/HTTP/Relay 실행 없음. 테스트가 만든 MySQL만 Testcontainers가 정리한다.
같은 승인 fixture17,000개를 매번 다시 사용, 테이블 내용 삭제와 issuedQuantity0 복원 후 측정. couponId/승인시각/requestId/userId 고정. DB AUTO_INCREMENT는 초기화하지 않음.
DB 트랜잭션은 TransactionTemplate 외부 경계, 기존 processReserved REQUIRED 참여. 내부 service 반환은 commit 이전이며 completed_return_ns는 외부 실제 commit/정리 이후다.
StatementInspector SQL 수 + Hibernate prepared/executed 횟수 대조. 실제 JDBC commit 성공 호출과 Hibernate 성공 transaction 수 대조. SQL/flush는 상세 결과 참조.
DB 중간 오류는 coupon_issue_result CHECK constraint의 5번째 user 삽입 실패. 단건은 첫 요청 실패. 기존 네 건 포함 전체 rollback 후 독립조회 검증. 같은 요청으로 retry/replay.
성능 계측은 전 실행 ON이며 별도 OFF 비교 없음. JDBC SQL batch, 서비스 코드/offset/Consumer 설정 변경 없음.

최초 성능 실행의 측정 원본: DbBatchExperimentTest-measured.java. 현재 소스는 @DirtiesContext(AFTER_CLASS) 추가로 테스트 종료 순서만 수정됐다. 수정 후 focused rollback 테스트1개를 별도 cleanup-validation에 재검증. 전체4회 성능은 최초 실행 자료다.
