승인 예약 Consumer→DB 연결 검증 — 2026-10-08
신규12개 + 기존 Processor9개 + Redis48개 + Relay9개 = 총78 통과.
실패/오류/건너뜀0. 실제 격리 MySQL8.0/Redis7-alpine Testcontainers 사용.
서비스 코드는 변경하지 않았다.

검증:
실제 유효 기간에 Redis 예약 생성 후 행사 종료까지 기다린 뒤 Consumer 호출→ISSUED 커밋.
동일 요청 재전달→기존 결과/발급ID 유지, 추가 수량 증가 없음.
메시지 couponId/userId/승인 시각 불일치3경우 차단.
예약 없음/승인 시각 없음 차단.
손상 예약을 주입해 승인 시각이 시작 전/종료 정각이면 DB 발급 차단.
Processor 직접 호출로 시작 정각 포함 규칙 확인(이 케이스는 Redis 승인 증명과 구분).
실제 MySQL CHECK 제약으로 결과 INSERT 실패→수량/발급이력/결과 전체 롤백.
Redis 예약·차감 재고는 보존, 제약 제거 후 같은 요청으로 정상 발급.
DB 상한에 도달한 불일치 상태를 주입하면 발급/REJECTED 기록/Redis 반환 없이 오류.

관측:
테스트 트랜잭션 NOT_SUPPORTED, Spring의 실제 Processor 트랜잭션 프록시 사용.
Consumer 호출 반환/예외 이후 별도 Repository 조회로 커밋/롤백 확인.
수량뿐 아니라 결과 requestId/couponId/userId/발급ID와 발급이력 대상도 대조.
DB LocalDateTime과 Redis Instant 변환에 Asia/Seoul 적용.

한계:
Kafka 브로커 전송/offset과 HTTP, 반복 Relay, DB 프로세스 중단·재시작은 미검증.
Consumer 메서드 직접 호출이다. DB 장애는 결과 INSERT 제약 실패로 주입했다.
기존 Kafka 복구 테스트는 이번 실행에 포함하지 않았다. 전체 프로젝트 테스트 통과라는 뜻이 아니다.

실행:
./gradlew test --tests com.assignment.coupon_system.issuerequest.consumer.ReservedCouponIssueIntegrationTest --tests com.assignment.coupon_system.issuerequest.service.CouponIssueProcessorTest --tests com.assignment.coupon_system.coupon.redis.CouponIssueRedisServiceTest --tests com.assignment.coupon_system.issuerequest.relay.CouponReservationRelayTest
실제 실행은 GRADLE_USER_HOME=/tmp/coupon-gradle-home, 로컬 Gradle8.14.4 --no-daemon 사용.
환경 이슈: 기존 임시 캐시의 groovy-dsl/transforms/workerMain 파일 누락으로 테스트 전 실패.
해당 디렉터리를 backup 이름으로 보존하고 Gradle이 재생성한 뒤 성공했다.
신규 테스트의 Container import 충돌을 명시적 import로 수정했다.
기존 앱/컨테이너는 유지, 테스트 컨테이너만 Testcontainers가 정리했다. 커밋/배포 없음.
